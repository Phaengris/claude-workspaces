**Goal:** The process layer — daemons with pid+starttime liveness, process-group TERM→KILL stop, and the commands `up`, `down`, `restart`, `logs`, `exec`, `browse`; `status` shows running daemons.

**Architecture:** `proc` gains the daemon primitives (start/stop/liveness — the riskiest code in the tool); `wsp` gains the daemon model (paths, enumeration from `start:` entries, target resolution per spec §2's grammar); `cli` wires six commands. **Tech Stack:** No new deps (syscall/os stdlib + existing x/sys). ACCELERATED MODE: binding contracts + named tests; reference code only where subtle. Real-process tests (spawn actual sleepers) — no mocks.

## Global Constraints

- Module/deps/exit codes/git-argv/doc-comment/gofmt-vet-test(+`-race` where concurrency)/conventional-commit+trailer `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>` — all as M2's plan; clean-room doctrine unchanged.
- POSIX/Linux-first: `/proc/<pid>/stat` field 22 for starttime (count fields AFTER the last `)` — comm may contain spaces/parens); macOS fallback = pid-only liveness with a documented degradation (spec §3).
- ALL user commands spawn via `proc.Run` / the new daemon starter with `wsp.CommandEnv` — no other exec path for user code.
- Daemon files: `<ws.Dir>/.workspace/pids/<project>:<daemon>` (one file per daemon, content `<pid> <starttime>\n`), logs `<ws.Dir>/.workspace/logs/<project>:<daemon>.log` and `.err.log`, truncated at each start (spec §2/§3; v1 kept per-start truncation).
- Target grammar (spec §2, decided in M1 spec round): `up|down|restart <ws> [target…]`; target = project name or daemon name; daemon name colliding across projects → error demanding `project:daemon`; explicit `project:daemon` always accepted; no targets = whole workspace. Single-daemon target still runs the owning project's ensure-chain first (`up`).
- Idempotence: `up` on running daemons = no-op for those; `down` on stopped = no-op; `restart` = down(confirmed) + up.

## Decided behaviors

| Topic | Decision |
|---|---|
| Liveness | pid file `<pid> <starttime>`; alive ⇔ `kill(pid,0)` succeeds (or EPERM) AND `/proc/<pid>/stat` starttime == recorded. Stale/corrupt/missing pid file = not running (and `up` may overwrite it) |
| Start | run-and-wait `start:` entries (bare strings) execute via `proc.Run` on EVERY `up` of that project, in listed order, BEFORE its daemons; daemons start with `Setpgid`, stdout→`.log`, stderr→`.err.log` (both O_TRUNC), process released (no wait) |
| Stop | SIGTERM to the process GROUP (-pgid) → poll liveness every 100ms up to 5s → SIGKILL group → poll up to 2s → error if still alive. Report which signal sufficed. Remove pid file after confirmed death |
| Order | `up`: projects in TopoOrder; within a project: run-and-waits then daemons in listed order. `down`: reverse everything |
| up setup | per project: EnsureProject FIRST (worktree+env+stamped setup — same chain as checkout), then start entries |
| restart | resolved targets: down (confirmed) then up; no explicit targets = all RUNNING daemons of the workspace… plus not-running ones too (restart = converge to running); i.e. restart ≡ down+up of the target set |
| logs | `logs <ws> <daemon-target>` prints the last 50 lines of `.log` then, with `-f`, follows both `.log`/`.err.log` by polling (500ms); `-n N` overrides count; missing log file → note + empty (exit 0 if daemon known, else 3) |
| exec | `exec <ws> [project] <cmd> [args…]` — true process replacement: `unix.Exec(resolvedPath, argv, env)`; path resolved with `exec.LookPath` under the CURATED env's PATH (temporarily set); env = `wsp.CommandEnv`; cwd = project dir if given (must be configured + checked out), else ws.Dir; the optional-project ambiguity: if args[1] names a configured project it IS the project — document that a command named like a project needs `--` or full path (v1 behavior) |
| browse | `browse <ws> [project]` — project defaulting: sole checked-out project, else required (usage error); URL `http://localhost:<port>` where port = project's `browse_port` after `Subst(RuntimeVars)`; empty browse_port → plain error 1; opens via `xdg-open` (LookPath; not found → print the URL instead, exit 0 — SSH-friendly) |
| status | per checked-out project, after the existing line: one line per configured daemon `    <daemon>: running (pid N)` / `stopped`; `--json` projects[] gains daemons:[{name, running, pid}] |
| exec/logs/browse | exec: workspace not found 3, project not configured 3, command missing → natural exec error 1. logs/browse target resolution errors per the target grammar (3 for unknown) |

### Task 1: proc — daemon primitives (start, liveness, stop)

**Files:** Create `internal/proc/daemon.go`, `internal/proc/daemon_test.go`.

**Produces (binding):**
- `proc.StartDaemon(dir, command string, env []string, logPath, errPath, pidPath string) error` — `$SHELL -lc <command>` (as Run), `Setpgid: true`, stdout/stderr to the two files (O_CREATE|O_WRONLY|O_TRUNC, 0644), start, write pidPath `<pid> <starttime>\n` (0644, parent dirs assumed), `cmd.Process.Release()`. Starttime read from `/proc/<pid>/stat`; if unreadable (non-Linux), write `<pid> 0` (0 = "no starttime check", documented degradation).
- `proc.ReadPidFile(pidPath string) (pid int, starttime uint64, err error)`; missing file → `fs.ErrNotExist` passthrough.
- `proc.Alive(pid int, starttime uint64) bool` — signal-0 (EPERM counts alive) AND (starttime == 0 OR `/proc` starttime matches).
- `proc.Starttime(pid int) (uint64, error)` — parse field 22 counting AFTER the last `)` in `/proc/<pid>/stat` (comm may contain spaces/parens — the classic bug; test with the real file).
- `proc.StopGroup(pid int, starttime uint64) (signal string, err error)` — per decided Stop row; returns "TERM"/"KILL"; not-alive at entry → ("", nil) no-op.

**Tests (real processes; `-race`):** start a real daemon (`sleep 30`), pid file exists + Alive true + starttime matches the live proc; StopGroup → TERM reported, process gone, Alive false; group semantics: daemon spawning a child (`sh -c 'sleep 30 & wait'`) — both die on StopGroup (check child pid unparented from us via pgid probe or just assert parent death + no orphan by pgid kill(‑pgid,0) failing); KILL escalation: a `trap '' TERM; sleep 30` daemon → StopGroup reports KILL within budget; Alive false for recycled-starttime (write pid file with wrong starttime for a live pid → Alive false); ReadPidFile corrupt content → error; log truncation across two starts.

**Complexity:** high — **Fable** (the riskiest code in the tool: pgroups, signals, /proc parsing).

- [ ] Failing tests → implement → `-race` + full suite → commit `feat(proc): daemon start, pid+starttime liveness, group stop`.
