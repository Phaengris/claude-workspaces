# Upgrading from claude-workspaces

chaban was called claude-workspaces before v2.0, and its command was
`workspace`. If you used that version, this page moves your setup over. If you
didn't, you don't need it.

What changed:

- The command is `chaban`. `chaban claude` is now `chaban chat`.
- The default root is `~/workspaces` (it was `~/claude-workspaces`).
- The root variable is `CHABAN_ROOT_DIR` (it was `CLAUDE_WORKSPACES_ROOT_DIR`).
- chaban no longer adds `--dangerously-skip-permissions` to `claude`. The
  `agent:` block in `config.yml` says how to start your agent.

The full list is in the [CHANGELOG](../CHANGELOG.md), under 2.0.0.

## Steps

In order:

1. Uninstall with the old binary: `workspace uninstall`.
2. Keep your old root. Set `CHABAN_ROOT_DIR` to it before installing, or
   `chaban install` stops on the old-root guard (see below). Use the value of
   `CLAUDE_WORKSPACES_ROOT_DIR` if you had one, otherwise
   `~/claude-workspaces`. Then unset the old variable.

   ```sh
   set -Ux CHABAN_ROOT_DIR ~/claude-workspaces     # fish
   export CHABAN_ROOT_DIR=~/claude-workspaces      # bash/zsh, in your rc file
   ```

3. Install: `chaban install`.
4. Replace the old entries. The old SessionStart hook in
   `~/.claude/settings.json` points at a script the old uninstall deleted. The
   old bash/zsh rc lines source files that are gone. Remove both, then add the
   ones `chaban install` prints. Fix any statusline command that calls
   `workspace`.
5. Add an `agent:` block to `config.yml`. Copy the Claude Code block from the
   README's [Agents](../README.md#agents) section. It keeps
   `instructions_file: CLAUDE.md`, the file your workspaces already have. Put
   `--dangerously-skip-permissions` into its `start` and `resume` if you want
   it back. Without a block, `chat` still starts `claude`, with a notice each
   time.
6. Fix one line in your workspaces' `CLAUDE.md` files. chaban writes that file
   once and never again, so one seeded line still says `workspace status`.
   See which files have it:

   ```sh
   grep -lx 'every substantial turn. The user reads it from outside via `workspace status`,' <root>/*/CLAUDE.md
   ```

   Then replace that exact line in those files. Nothing else changes:

   ```sh
   sed -i.bak 's/^every substantial turn\. The user reads it from outside via `workspace status`,$/every substantial turn. The user reads it from outside via `chaban status`,/' <those files>
   ```

   The `.bak` copies stay until you delete them.
7. Restart agent sessions running inside workspaces. They still know the old
   skill and command, and their environment lacks `CHABAN_ROOT_DIR`.

Each workspace's `WORKSPACE.md` still says `` Generated by `workspace` ``
until the next `chaban up` or `checkout` writes it again. That is harmless.

## The two guards

Two checks stop an old setup from quietly starting over with an empty root.
Both exit 4 (config error), and the message says what to do.

### "CLAUDE_WORKSPACES_ROOT_DIR is no longer read"

`CLAUDE_WORKSPACES_ROOT_DIR` is set and `CHABAN_ROOT_DIR` is not. chaban never
reads the old variable; it only notices it. The message:

```
CLAUDE_WORKSPACES_ROOT_DIR is no longer read: rename it to CHABAN_ROOT_DIR
```

### "exists, but the default root is now ~/workspaces"

No root variable is set, `~/workspaces` doesn't exist, and
`~/claude-workspaces` does. The message, with your home in place of `~`:

```
~/claude-workspaces exists, but the default root is now ~/workspaces: set CHABAN_ROOT_DIR=~/claude-workspaces to keep using it
```

This one also stops `chaban install`, which would otherwise create an empty
`~/workspaces` beside your real root. It goes quiet once `~/workspaces`
exists or a root variable is set.

## Keeping the old root

If you keep `~/claude-workspaces` through `CHABAN_ROOT_DIR`, every process
that runs `chaban` needs the variable, including commands chaban runs for you
and Claude Code started outside your shell. How to make sure it arrives is in
[`reference.md`](reference.md#the-variable-must-reach-every-process).

Moving the root to `~/workspaces` instead is possible, but it takes care: see
[Moving a root](reference.md#moving-a-root).
